# «ЗАЛЁТ» Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Браузерная онлайн-игра про кейсы для компании друзей: серверная экономика на Supabase, provably fair, батлы в реальном времени, премиальный тёмный интерфейс.

**Architecture:** Чистая логика (каталог, ролл, апгрейд, контракт, батл) живёт в `src/shared` и зеркалится в PL/pgSQL; конфиг из `src/config/economy.ts` генерируется в `supabase/seed.sql`. Клиент ходит только в RPC, Realtime лишь «пинает» общий `sync`.

**Tech Stack:** Vite, React, TypeScript, Zustand, Framer Motion, Howler, Tailwind v4, lucide-react, react-router (Hash), @supabase/supabase-js, Vitest, Playwright, Postgres 16 (локально для тестов), tsx.

**Spec:** `docs/superpowers/specs/2026-11-10-zalet-design.md` (+ `PROMPT.md`)

## Global Constraints

- Валюта только виртуальная; никаких платежей, вывода, обмена.
- Интерфейс на русском. Без чужих брендов, логотипов, названий скинов, графики.
- Деньги — целые копейки (`bigint`, 1 монета = 100). Клиент баланс не меняет.
- Все числа экономики — только в `src/config/economy.ts`.
- RLS включён на всех таблицах; у клиента нет `insert/update/delete`.
- Ключи Supabase только в `.env` (в `.gitignore`), в репозитории — `.env.example`.
- Секретные рецепты контрактов описываются только в `SECRETS.md`; в UI, спеке, плане и тестах их нет.
- Адаптив 375–1440 px без горизонтального скролла; `prefers-reduced-motion` уважается.
- `ticket = n0 mod 1_000_000_000`; `fi = n1 mod 10000`; счётчик при `n2 mod 10000 < 1000`;
  цена экземпляра `floor(base × (12000 − 4·fi) / 10000)`, со счётчиком `floor(price × 3 / 2)`.

## Review Focus

1. Двойной клик / параллельные RPC с двух устройств → деньги не списываются и не начисляются дважды (`for update` по профилю; тест `concurrent open_case`).
2. Устаревший клиент продаёт/вкладывает предмет, которого уже нет → понятная ошибка и пересинхронизация, баланс не меняется (тест `sell missing item`).
3. Создатель батла ушёл из лобби / закрыл вкладку → все взносы возвращаются, батл отменён (тест `battle_leave refunds`).
4. Клиент и сервер на разных версиях конфига → баннер, игра не ломается (тест `cfg version` в sync).
5. Телефон уснул посреди анимации батла → после возврата комната показывает корректную фазу по серверному времени (e2e: reload посреди батла).

### Task 2: Экономика и каталог (TDD)

**Files:** `src/config/economy.ts`, `src/config/cases.ts`, `src/config/weapons.ts`, `src/shared/{money,catalog,roll}.ts`, `tests/{catalog,roll}.test.ts`

**Interfaces (Produces):**
- `CATALOG: { cases: CaseDef[]; caseById: Map<string, CaseDef>; itemById: Map<string, ItemDef>; outcomes: FlatOutcome[]; version: string }`
- `CaseDef { id, name, price, rtp, category, profile, theme, items: ItemDef[], outcomes: Outcome[], k }`
- `Outcome { idx, itemId, phase, weight, cum, price }` (Σweight = `TICKETS = 1e9`, `cum` — верхняя граница)
- `pickOutcome(c: CaseDef, ticket: number): Outcome`
- `instancePrice(base: number, fi: number, st: boolean): number`
- `rollDrop(c: CaseDef, n: RollNums): Drop` где `RollNums { n0, n1, n2, n3 }`, `Drop { caseId, outcomeIdx, itemId, phase, fi, st, price }`
- `wearIndex(fi: number): 0..4`, `expectedValue(c: CaseDef): number` (точное матожидание в копейках)

- [ ] Тесты (сначала красные):
  - `catalog`: кейсов ≥ 40; у каждого Σweight === 1e9; id предметов уникальны; у каждого кейса из `economy` есть контент и наоборот;
  - `catalog`: `|expectedValue(c)/c.price − c.rtp| < 0.002` для всех кейсов; RTP каждого в [0.90, 0.95] (кроме бесплатного);
  - `catalog`: шансы редкостей стандартного профиля === таблице из ТЗ (60/22/10.5/4.8/1.85/0.58/0.22/0.05);
  - `roll`: `pickOutcome` на границах `cum−1`/`cum`; `instancePrice(1000,0,false)===1200`, `(1000,5000,false)===1000`, `(1000,9999,false)===800`, `(1000,5000,true)===1500`;
  - `roll`: ножи/перчатки никогда не получают счётчик; фазы встречаются только у ножей/перчаток с долями 85/12/2.7/0.3.
- [ ] Реализация → зелёные тесты → commit.

### Task 4: Апгрейдер, контракты, батлы — чистая логика (TDD)

**Files:** `src/shared/{upgrade,contract,battle,progress}.ts`, `tests/{upgrade,contract,battle}.test.ts`

**Produces:**
- `upgradeChancePpm(input: number, target: number): number` (floor(input×950000/target)); `upgradeAllowed(ppm): boolean` (10 000…750 000); `upgradeWin(ppm, n0): boolean` (`n0 mod 1e6 < ppm`)
- `contractCheck(items: {rarity:number; price:number}[]): {ok: true; rarity: number; sum: number} | {ok: false; error: string}`
- `contractMult(n0, n1): number` (промилле), `contractResult(sum, rarity, n: RollNums): {caseId, outcomeIdx, itemId, phase, fi, price}`
- `slotsOf(format)`, `teamOf(format, slot)`, `resolveBattle({mode, format, values: number[][], tie: number}): {sums: number[]; teamSums: number[]; winnerTeam: number; payouts: number[]; pot: number}`

- [ ] Тесты:
  - upgrade: 100→200 даёт 475 000 ppm; <1 % и >75 % запрещены; EV по 1e6 ppm-роллов = 0.95 ± 0.001;
  - contract: <3, >10, разные редкости, контрабанда → ошибка; среднее `contractMult` по сетке ∈ [0.90, 0.95]; результат всегда редкости +1 и цена в ±20 % от базовой цены исхода;
  - battle: classic/crazy/terminal/shared/jackpot на фиксированных значениях; 2v2 делит банк пополам; ничья решается `tie`; Σpayouts ≤ pot и ≥ pot − slots.
- [ ] Реализация → зелёные → commit.
